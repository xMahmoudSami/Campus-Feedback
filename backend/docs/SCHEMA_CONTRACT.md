# Database Schema Contract

This document documents the authoritative PostgreSQL database schema implemented in `database/init.sql` and consumed by the backend.

## Overview of Conceptual Tables

| Table | Purpose | Primary Key | Foreign Keys & Cascades | Constraints |
| :--- | :--- | :--- | :--- | :--- |
| `users` | User accounts and roles (`admin`, `student`) | `id` (SERIAL) | None | `email` UNIQUE, `username` UNIQUE |
| `surveys` | Surveys created by administrators | `id` (SERIAL) | `created_by` -> `users(id)` | `status IN ('draft', 'published', 'closed')` |
| `questions` | Questions within a survey | `id` (SERIAL) | `survey_id` -> `surveys(id)` ON DELETE CASCADE | `question_type IN ('rating', 'text', 'multiple_choice')` |
| `survey_responses` | Student survey attempts and completion status | `id` (SERIAL) | `survey_id` -> `surveys(id)` ON DELETE CASCADE, `student_id` -> `users(id)` ON DELETE CASCADE | `UNIQUE (survey_id, student_id)`, `status IN ('in_progress', 'completed')` |
| `answers` | Answers per question for each response | `id` (SERIAL) | `response_id` -> `survey_responses(id)` ON DELETE CASCADE, `question_id` -> `questions(id)` ON DELETE CASCADE | `UNIQUE (response_id, question_id)`, `rating BETWEEN 1 AND 5` |
| `feedback` | Comments and suggestions from students | `id` (SERIAL) | `student_id` -> `users(id)` ON DELETE CASCADE, `survey_id` -> `surveys(id)` ON DELETE SET NULL | `message NOT NULL` |
| `survey_views` | Views of a survey by students | `id` (SERIAL) | `survey_id` -> `surveys(id)` ON DELETE CASCADE, `student_id` -> `users(id)` ON DELETE CASCADE | `viewed_at NOT NULL` |

---

## Key Rules & Constraints

1. **User Accounts & Authentication**:
   - Roles: `'admin'`, `'student'`.
   - Passwords stored as bcrypt hashes (generated by Node `bcrypt`/`bcryptjs` or PostgreSQL `pgcrypto` `crypt()`).
   - Login supports either `username` or `email`.
   - No public registration endpoint.

2. **Survey Status Lifecycle**:
   - Status: `'draft'`, `'published'`, `'closed'`.
   - Students can only see `'published'` surveys.
   - When published, `published_at` is set.
   - When closed, `closed_at` is set, and new responses are rejected.

3. **Question Types & Options**:
   - Types: `'rating'`, `'text'`, `'multiple_choice'`.
   - `options` is stored as a `JSONB` array of strings (e.g. `["Too slow", "Just right", "Too fast"]`).
   - Rating questions require an integer between `1` and `5`.
   - Questions are ordered by `position ASC, id ASC`.

4. **Response Integrity & Deduplication**:
   - A unique constraint `UNIQUE (survey_id, student_id)` on `survey_responses` guarantees one attempt per student per survey.
   - Finished submissions set `status = 'completed'` and `completed_at = NOW()`.
   - Database transactions wrap the creation of `survey_responses` and `answers`.

5. **Feedback**:
   - Students can submit general feedback or link it to an optional `survey_id`.
